# Ordinary Constraints workflow

Requirement-derived browser checks for parent-edge controls, native resize relationships, indicators, atomic history and persistence live here.
The owning runner is ../check-constraints.ts, exposed as check:constraints.
It checks development and built modes, records actual browser/source identities, commands, screenshots and traces, and owns its application processes.
The fixtures use ordinary canonical nodes and saved CSS, not a separate layout model.
Native experiments under .unlazy/v1-constraints isolate platform mapping before product verification.
Source-backed React, MCP production integration, Windows and unfinished product image/PDF exporters remain separate milestones.
The matrix also verifies existing Fill children inside constrained Rows and opted-in Columns, refusal of unresolved parent supply, stale preparation after a protected draft, and stable keyboard focus while measured position readouts update during a native transition.
The current mapping also checks fixed-descendant containment, browser shorthand serialization, replaced/native input sizing and simultaneous min/max limits under overconstrained insets.
Center adds no transform, and Both-edge alignment preserves the approved start-edge priority.
